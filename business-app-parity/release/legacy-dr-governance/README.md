# Legacy Doomsday policy review — not a deployment package

PR149 deliberately excluded the old repository-root scripts. These three exact, SHA256-checked text copies retain the original branch/commit, Worker/D1/no-R2, two-phase provenance and command-ordering contract for read-only regression. They are not executable launchers and must never be invoked by CI. The actual original root deployment entry point must remain absent in this app-only integration; adding it requires a separately reviewed complete toolchain and explicit target authorization.

Dependency review: the wrapper requires Git branch/origin equality, the prepared fire-app-dr directory, Python provenance verification before migration and before deployment, compiled independent Wrangler config, then pnpm/Wrangler. The provenance verifier requires every governed script/patch in the 49-entry inventory, v138 sealed provenance, all source/build/migration hashes, capture identity, six governed overlay documents, parity/forward-sync manifests and the full persistent evidence tree. contract.json records the exact original Git blobs and external inputs; those runtime dependencies have NOT been imported or reconstructed here. Importing only the wrapper would create an incomplete operational chain.

The regression still executes every original policy assertion and all six negative controls, additionally verifies archive hashes and dependency inventory, and refuses a newly introduced root deploy wrapper. A passing test means the historical safety contract remains checked and the incomplete legacy deploy path stays unavailable. It does not verify current hosted provenance, authorize remote commands, or close any release gate. Existing app-owned materialization/runtime-config/release-review tests remain independent.

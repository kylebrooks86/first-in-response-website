# Customizable pricing candidate — source only

All 30 catalog entries and factory defaults remain unchanged, including house wash 22 cents/sq ft, gutters 150 cents/linear ft and fence 40 cents/sq ft. Settings → Standard starting prices manages deliberate persistent overrides. A separate namespaced row per service (`fire:service-rate:v1:<id>`) uses the existing backed-up `message_templates` override table. Template keys/content are untouched; the template endpoint returns only its known template catalog. No schema migration or hosted action is required by this feature.

Owner-only GET/PUT use uncached responses, integer cents, strict request fields, server revisions and atomic compare-and-swap. Repeating an already-committed absolute value does not write again. A stale device cannot overwrite a different current value. Invalid stored settings fail closed; selecting/resetting a standard is disabled until verified. Existing draft selections never reprice after a standards refresh.

New/edit estimate service controls offer per-unit rate, flat service amount and explicit reset to the current standard. Custom service names, descriptions and quantities remain editable. Flat totals retain measured quantities. Standard-setting changes never mutate estimates, invoices, payments or signatures. Existing estimate APIs and approval/payment/invoice editing restrictions are unchanged. Existing $150 minimum, discount cap and 50% deposit logic remain unchanged; no new pricing floor or promotion rule was introduced.

Legacy items store quantity and agreed total, not the original pricing method. Reopened estimates therefore start with fixed saved service totals; this also preserves a flat quote exactly. Descriptive/measurement edits keep that amount until the owner chooses Per unit or Reset to standard. No guessed rounded rate silently rewrites the saved total. Customer documents receive only the existing agreed line fields, never internal settings/reset explanations.

Verification includes actual SQLite pricing routes, duplicate/competing saves, original signed-estimate/invoice/payment preservation, exact-cent parsing, flat/reset calculations and existing discount arithmetic.

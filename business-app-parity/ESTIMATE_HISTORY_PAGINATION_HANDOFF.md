The Estimates screen previously fetched a maximum 100 estimates and the API fetched every estimate item. The isolated candidates now use dedicated authenticated GET /api/estimate-history. This leaves the existing financial API/caller contracts unchanged. History uses 1..50-record pages with deterministic created_at/id descending keyset cursors and parameterized SQL. Item queries bind only the identities in the returned page. Optional focus reads one exact estimate; server-side search/status filtering applies across history rather than only loaded rows. Literal LIKE wildcards are escaped. Invalid limits, filters and cursors fail closed before queries.

The existing screen has a compact Search estimate history field, older-record loading, explicit retry, and a loaded-record count. Failed pages retain loaded rows. Pending pagination no longer hides the selected estimate detail; native browser testing edited a quantity while a page was held, then verified every form field survived the append. New pages deduplicate IDs and keep existing record objects. List status and pipeline navigation are retained; returning to Pipeline clears the list-only status filter. Pipeline totals are labeled as loaded-record totals, not global financial reporting. Older focused notification lookup is supported through the bounded API, but notification-triggered UI selection was not independently exercised in this batch.

# FIRE G6 owner customer create/edit browser-boundary repair — 2026-11-19

## Actual source defect and correction (draft PR #270, NO DEPLOY)

The existing `shared/app/api/customers/route.ts` uses a separate 64,000-byte strict streaming `readCustomerRequest` body parser for both owner-only `POST` and `PATCH`. The Nov 19 hardened shared `readOwnerWriteObject` browser-origin checks did **not** automatically reach these two routes. After the existing owner authorization, cross-site browser/form submissions could reach the customer parser without the exact-Origin / Fetch-Metadata boundary now enforced on other owner-write routes. Owner authorization alone does not supply a CSRF boundary.

[Actual code fix `632edce7b868196fd0b7d6d08866838841de8b5c`](https://github.com/kylebrooks86/first-in-response-website/commit/632edce7b868196fd0b7d6d08866838841de8b5c) applies the **already-existing** `ownerBrowserWriteScope(request, true)` at the start of BOTH customer write handlers **before** parsing, customer lookup or D1 operations. This requires exact same-origin browser `Origin`, allows only `Sec-Fetch-Site: same-origin` if present, rejects simple form/text browser submissions, and preserves nonbrowser/synthetic authenticated caller behavior. The former bounded 64 KiB UTF-8 parser, Content-Length integrity checks, permanent Customer #, duplicate-identity checks, readback, CAS and lost-D1-ACK idempotency code were not changed. No new Worker runtime module or R2 resource.

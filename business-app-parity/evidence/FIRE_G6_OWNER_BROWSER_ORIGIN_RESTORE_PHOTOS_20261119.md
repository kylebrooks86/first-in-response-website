# FIRE Gate 6 — owner browser-origin protection, records restore and photo upload (2026-11-19)

## Goal and verified source scope
The owner-only JSON read helper previously bounded requests but did not inspect browser Origin / Fetch Metadata. In the candidate owner app, an authenticated browser request from an unrelated origin or a sibling subdomain must **not** reach owner D1 or Stripe writes, an archival restore, or photo storage. This is defense in depth, not a hosted Cloudflare Access policy or an alternative to genuine owner/nonowner denial.

**Draft PR #270 only; no merge or deployment.** Current code/test head before this report: `67d2608928438f39e09fe4efaf5961c4085e14ff`.

## Concrete executable changes

1. [Initial owner JSON browser-boundary source `2168930`](https://github.com/kylebrooks86/first-in-response-website/commit/216893098333791c1bbc2682853efb852f1e8efc): checks explicit browser `Origin` against the **exact request URL origin**, rejects `Sec-Fetch-Site` values other than `same-origin` and requires `application/json` for browser-originated JSON owner writes, before reading body bytes or accessing D1/Stripe. Existing body-size, streaming and JSON checks remain. Browser metadata absent is allowed for existing internal/synthetic callers; those remain separately owner-authenticated and bounded.
2. [Shared helper finalized `58998d7`](https://github.com/kylebrooks86/first-in-response-website/commit/58998d73aadffce6a42d4fe0feb5be6a47942679): `ownerBrowserWriteScope(request,requireJson)` is reused by the owner JSON parser and two additional sensitive routes. An earlier intermediate refactor commit was corrected before acceptance; it was never hosted.
3. [Records restore route `3730d38`](https://github.com/kylebrooks86/first-in-response-website/commit/3730d381ce916f58f2e321d3a51ef27ed55465f1) now rejects browser-origin violations **after owner authentication but BEFORE** numbered-identity D1 reads, restore JSON parsing or writes. Valid browser JSON restore retains its existing 5 MB bounded parser, numbered-feature lock and record/ledger integrity checks.
4. [Photo upload route `23a0789`](https://github.com/kylebrooks86/first-in-response-website/commit/23a0789970534cb60506476d3ef22cb75e1a12f1) now denies cross-origin browser uploads **before** any bucket/body processing. Same-origin multipart remains allowed by the origin helper and is still subjected to its pre-existing strict multipart/size/ownership validation. **No R2 bucket or subscription was created**.
5. [Test additions `55a77c8`](https://github.com/kylebrooks86/first-in-response-website/commit/55a77c8ee1e0641b08ff46fa4177a82e5a22f736) and [expanded backup/photo cases `0fe33eb`](https://github.com/kylebrooks86/first-in-response-website/commit/0fe33ebd89caa0692e978443c0d2d93ab0c3a929) verify synthetic real-code accepted same-origin JSON and multipart, rejected foreign/sibling origins, `cross-site`, `same-site`, navigation/null fetch contexts, wrong text/form media types, non-browser compatibility and exact route guard ordering. The first new source-order assertion erroneously found `GET` backup auth rather than `POST`; [fixed the test anchor `67d2608`](https://github.com/kylebrooks86/first-in-response-website/commit/67d2608928438f39e09fe4efaf5961c4085e14ff), without weakening production checks.

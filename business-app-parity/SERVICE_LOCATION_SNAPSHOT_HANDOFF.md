The synthetic development capability now atomically saves an immutable service-address snapshot with each newly created estimate. The existing estimate, customer and service-line inserts plus snapshot insertion use one actual D1 batch transaction. An existing customer's submitted service address is captured without changing that customer; when the request omits address, its current customer address is captured. An explicitly blank address remains blank and does not silently fall back to another location. Separate estimates can preserve different locations for one customer. This is the required location foundation, not a completed properties UI.

The reviewed SQL adds estimate_service_locations keyed by estimate identity, with customer and estimate references, customer-match validation and update/delete rejection triggers. It is stored outside all migration journals and was applied only to disposable synthetic D1 fixtures. No existing table was altered and no historical location was backfilled. ORM declarations describe the candidate schema but do not apply it. Proper production migrations, checksums, schema checks, backups and rollback approval remain required before activation.

Shared readers use a fixed SQL helper to retrieve captured locations for estimate lists, bounded history/search, follow-ups, initial/refreshed dashboard, customer job history, invoices, and estimate/invoice/payment documents. Message templates use the estimate's service address rather than the customer's default. Captured empty strings remain empty. Legacy records retain the existing current-address display and receive serviceAddressSource=legacy-current-unverified; estimate detail and public documents warn that the original location was not recorded. Original historical addresses cannot be reconstructed from the mutable customer address. Invoice identity, totals, payments, service items, existing financial rules and customer addresses remain separate.

The FIRE_SERVICE_LOCATIONS_CANDIDATE capability is emitted only for explicitly opted-in development fixtures.
